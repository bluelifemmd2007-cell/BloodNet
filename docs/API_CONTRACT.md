# راهنمای API

این راهنما رفتار API برنامه را توضیح می‌دهد. قرارداد ساختاری کامل در بستهٔ محلی `participant_kit/openapi.yaml` قرار دارد و FastAPI نیز مستندات تعاملی را در `/docs` ارائه می‌کند.

## نشانی‌های API

| روش | مسیر | کاربرد |
|---|---|---|
| `GET` | `/health` | بررسی سلامت Backend |
| `GET` | `/hospitals` | دریافت بیمارستان‌های شناخته‌شده |
| `POST` | `/requests` | ثبت درخواست جدید |
| `GET` | `/requests` | فهرست درخواست‌ها |
| `GET` | `/requests/{request_id}` | مشاهدهٔ خلاصهٔ یک درخواست |
| `POST` | `/requests/{request_id}/approve` | تصمیم هماهنگ‌کننده برای درخواست در انتظار |
| `POST` | `/requests/{request_id}/amend` | تغییر فوریت درخواست فعال |
| `POST` | `/requests/{request_id}/cancel` | لغو درخواست |
| `POST` | `/callbacks/donor-response` | ثبت پاسخ اهداکننده |
| `POST` | `/callbacks/donor-progress` | ثبت رویداد پیشرفت اهدا |
| `POST` | `/callbacks/gateway-status` | ثبت وضعیت پیام Gateway |
| `GET` | `/operations/snapshot?hospital_id={id}` | دادهٔ زندهٔ موردنیاز داشبورد |

## احراز هویت و تکرارپذیری

مسیرهای بیمارستانی از سربرگ `Authorization: Bearer ...` و token تنظیم‌شده با `HOSPITAL_TOKEN` استفاده می‌کنند. مسیر تأیید به `COORDINATOR_TOKEN` نیاز دارد. مقادیر پیش‌فرض فقط برای تمرین محلی‌اند.

در `POST /requests` سربرگ `Idempotency-Key` الزامی است. ارسال دوبارهٔ همان کلید و همان بدنه، همان درخواست را برمی‌گرداند؛ استفادهٔ دوباره از کلید با بدنهٔ متفاوت رد می‌شود.

در callbackها، `event_id` کلید یکتای رویداد است. دریافت دوبارهٔ همان رویداد شمارنده‌ها را دوباره تغییر نمی‌دهد.

## اعتبارسنجی درخواست

- گروه‌های مجاز: `O+`, `A+`, `B+`, `AB+`, `O-`, `A-`, `B-`, `AB-`
- فرآورده‌ها: `red_cells`, `platelets`, `plasma`
- فوریت‌ها: `critical`, `urgent`, `planned`
- تعداد واحد: عدد صحیح از ۱ تا ۲۰
- بیمارستان باید در دادهٔ محلی ثبت شده باشد.
- بدنه‌های API فیلد اضافی نمی‌پذیرند، مگر آنجا که مدل مسیر خلاف آن را مشخص کند.

## چرخهٔ درخواست

- درخواست معمولی با وضعیت `open` آغاز می‌شود؛ قاعدهٔ بازبینی می‌تواند آن را به `pending_review` ببرد.
- درخواست در انتظار بررسی تا تأیید هماهنگ‌کننده وارد گردش تأمین نمی‌شود.
- `cancelled`، `expired` و `fulfilled` وضعیت‌های پایانی‌اند.
- `confirmed` به معنی پذیرفتن دعوت است، نه تحویل خون.
- شمارندهٔ اهدای انجام‌شده از مقدار تحویل‌شده جداست. تأمین اهداکننده پس از ETA پردازش و حمل محاسبه می‌شود.
- `stock_inflight` و `stock_fulfilled` به‌ترتیب واحدهای ارسالی در مسیر و تحویل‌شده را نشان می‌دهند.

## snapshot داشبورد

`GET /operations/snapshot` به token بیمارستان نیاز دارد و درخواست‌ها، موجودی زنده، ارسال‌ها، دعوت‌ها و رویدادهای اخیر را برمی‌گرداند. اگر Inventory پاسخ معتبر ندهد، endpoint خطای `503` می‌دهد؛ در دسترس نبودن سرویس به‌صورت موجودی صفر جا زده نمی‌شود.

## پاسخ‌های خطا

خطاهای ورودی و وضعیت درخواست با کد HTTP و بدنهٔ JSON دارای شیء `error` بازگردانده می‌شوند. کدهای متداول شامل `400` برای ورودی یا کلید نامعتبر، `401` برای token نامعتبر، `404` برای شناسهٔ پیدا‌نشده، `409` برای گذار وضعیت نامعتبر، `422` برای تعارض کلید idempotency و `503` برای وابستگی محلی غیرقابل‌دسترس است.
